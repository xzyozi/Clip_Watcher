# 調査結果: クイックタスクの削除と多重起動について

> **アーカイブ資料**: 本書は当時の調査・提案であり、現行仕様の正本ではありません。現行コードおよび `docs/design/` を確認してください。

## 概要
本ドキュメントは、以下の2つの機能提案に関する調査結果をまとめたものです。
1. **クイックタスク項目の削除:** 使用後にクイックタスクの項目を削除するかどうかを切り替えるオプションの追加。
2. **多重起動のサポート:** アプリケーションの複数のインスタンスを同時に実行できるようにするオプションの追加。

## 1. クイックタスク項目の削除

### 現在の動作
現在、ユーザーが「クイックタスク」ダイアログ（メインメニューまたはショートカットからアクセス）で項目を選択すると、その項目はクリップボードにコピーされ、リストから**即座に削除**されます。この動作は `QuickTaskDialog` クラスの `_copy_selected` メソッド内でハードコーディングされています。

### 提案される実装
ユーザーの要望に基づき、この設定は**クイックタスクダイアログ内でのみ**完結させます。メイン設定ウィンドウには項目を追加しません。

#### 必要な変更:

1. **設定の保存（デフォルト値）:**
    - ファイル: `src/core/config/defaults.py`
    - アクション: `DEFAULT_USER_SETTINGS` に `"quick_task_delete_on_copy": True` を追加します（状態の永続化のため）。

2. **ダイアログロジックの更新:**
    - ファイル: `src/gui/windows/quick_task_dialog.py`
    - アクション:
        - `__init__` メソッドを更新し、`settings_manager` を受け取るようにします。
        - UIの下部（ボタンフレーム周辺）に `tk.Checkbutton` を追加します（例: "コピー後に削除"）。
        - チェックボックスの初期状態を `settings_manager` から読み込みます。
        - `_copy_selected` メソッドを更新し、チェックボックスの状態を確認して削除するかどうかを決定します。
        - チェックボックスの状態が変更された場合（またはダイアログを閉じる際）に、新しい値を `settings_manager` に保存します。

3. **ダイアログへの設定マネージャーの引き渡し:**
    - ファイル: `src/event_handlers/history_handlers.py`
    - アクション: `handle_create_quick_task` 内で、`self.app.settings_manager` を `QuickTaskDialog` コンストラクタに渡します。

## 2. 多重起動のサポート

### 現在の動作
アプリケーションは、ポート `61957` でのTCPソケットロックを使用して、単一インスタンスのみの実行を厳密に強制しています。このロジックは `src/event_handlers/__init__.py` の `start_app` 関数に存在します。ポートが既に使用されている場合、アプリケーションは「既に起動しています (Already Running)」というメッセージを表示して終了します。

### 提案される実装
多重起動を許可するには、ユーザー設定に基づいてこのロックチェックを回避する必要があります。ロックチェックは起動プロセスの非常に早い段階（アプリケーションのコンテキストが完全に読み込まれる前）に行われるため、この設定を確認するための軽量な方法が必要です。

#### 必要な変更:

1. **設定の追加:**
    - ファイル: `src/core/config/defaults.py`
    - アクション: `DEFAULT_USER_SETTINGS` に `"allow_multiple_instances": False` を追加します。

2. **起動ロジックの修正:**
    - ファイル: `src/event_handlers/__init__.py`
    - アクション:
        - `start_app` 内で、ソケットバインディングブロックの前に `settings.json` へのパスを構築します。
        - JSONファイル（存在する場合）を手動で読み込み、`"allow_multiple_instances"` キーを確認します。
        - キーが true の場合、ソケットバインディング/チェックブロック全体をスキップします。
        - ロックソケットが作成された場合は、適切に管理（クローズ）されるようにします。

3. **UI設定:**
    - ファイル: `src/gui/windows/settings_window.py`
    - アクション: 設定ウィンドウ（「一般」セクション下）に、この値を切り替えるためのチェックボックスを追加します。
    - *注:* この設定は*次の*インスタンスから有効になるため（設定変更後即座に別のインスタンスが起動できるようになりますが）、再起動が必要である旨をユーザーに警告した方が良いかもしれません。

## 結論
クイックタスクの変更はダイアログ内で完結し、ユーザビリティを向上させます。多重起動の変更は起動プロセスに介入します。どちらも既存のアーキテクチャと整合性を保ちながら実装可能です。
