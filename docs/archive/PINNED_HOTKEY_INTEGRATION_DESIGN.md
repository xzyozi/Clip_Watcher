# ピン留め履歴と個別グローバルホットキーの連携（前身設計）

> **アーカイブ資料**: 本書は `CLW-DD-001` の前身設計です。現行仕様は [CLW-DD-001_設定画面スキーマ駆動化とグローバルホットキー連携詳細設計書.md](../design/CLW-DD-001_設定画面スキーマ駆動化とグローバルホットキー連携詳細設計書.md) および `src/core/hotkey/` を確認してください。

## 1. 目的

ピン留め済みのクリップボード履歴へ個別のグローバルホットキーを割り当て、押下時に対象内容をクリップボードへ設定して、ホットキー押下時点でアクティブだったウィンドウへ自動貼り付けする。既存の表示/最小化ホットキーも同じ登録基盤で管理し、Windows API の登録・競合・解除の詳細を呼び出し元から隠蔽する。

本機能は Windows を対象とする。自動貼り付けは `Ctrl+V` のキーストローク送信で行い、クリップボードを更新できた場合でも送信に失敗する可能性がある。

---

## 2. スコープ

- ピン留め済みの履歴項目に対する割当、変更、解除
- 履歴一覧で、ホットキーが割り当てられたピン留め履歴にキー組合せを表示
- 複数の `RegisterHotKey` 登録と `WM_HOTKEY.wParam` による振り分け
- `settings.json` への割当の永続化、起動時の再登録
- 割当発火時のクリップボード設定、既存通知音、アクティブウィンドウへの自動貼り付け
- ピン解除・履歴削除・全履歴削除時の割当解除

対象外は Linux/macOS 対応、主キーとしての英数字以外のキー、複数選択への一括割当である。

## 3. データモデル

`pinned_hotkey_bindings` は `settings.json` に保存する。JSON オブジェクトのキーは履歴IDの文字列表現、値は正規化済みキー文字列とする。

```json
{
  "pinned_hotkey_bindings": {
    "42": "Ctrl+Alt+1"
  }
}
```

履歴項目は表示順でなく SQLite の `ClipboardHistoryDTO.id` により識別する。読み込み時は、正の整数ID・非空文字列・有効なキー書式だけを採用する。無効値、重複キー、存在しない項目、ピン留めされていない項目は登録対象から除外する。

履歴一覧は、ピン留め済みかつ `pinned_hotkey_bindings` に対応するIDを持つ項目だけにキー組合せを表示する。通常履歴およびホットキー未設定のピン留め履歴では、ホットキー列を空欄とする。

## 4. モジュール設計

### `GlobalHotkeyListener`

複数の `HotkeyRegistration` を単一の Windows メッセージスレッドで登録・解除する深いモジュールとする。集合登録の正規Interfaceは `start_many(registrations) -> bool` と `stop()` であり、ID採番、Win32 API、スレッド、`after()` によるメインスレッド復帰を実装内に隠蔽する。表示/最小化キーだけを扱う既存呼び出しには、予約ID `1` を使って `start_many()` へ委譲する互換API `start(modifiers, vk_code) -> bool` を提供する。

### `HotkeyRegistrationManager`

`reconfigure_all(global_enabled, global_combo, pinned_bindings) -> bool` を唯一の集合再構成 Interface とする。表示/最小化キーには予約ID `1` を使い、ピン項目には連番IDを割り当てる。候補集合の書式・重複を検証後に登録し、失敗時は旧集合を復元する。

`hotkey_id` から履歴IDを取得する Interface だけを `MainApplication` へ公開し、GUIや履歴サービスは Win32 の登録詳細を持たない。これにより、呼び出し側はIDとキー文字列だけを扱え、登録集合の原子的なロールバックが局所化される。

### `MainApplication`

`MainApplication` は `get_pinned_hotkey_bindings() -> dict[int, str]` を公開し、現在ピン留めされている履歴の表示用ホットキー割当をGUIへ提供する。GUIはこのInterfaceを使って履歴一覧を更新し、設定の永続化形式やホットキー登録の詳細には依存しない。

割当の設定・変更・解除・一括解除が成功した後、`MainApplication` は履歴一覧を再描画する。これにより、ホットキー列は次の履歴更新を待たずに最新の割当状態を表示する。

### `WindowsPasteSender`

`paste_active_window() -> bool` だけを公開するアダプターとする。`MainApplication` はクリップボード更新から75ms後にこの Interface を呼び、Windows の入力ストリームへ `Ctrl+V` を送る。キーストローク送信の失敗はログへ記録するが、設定済みのクリップボード内容はロールバックしない。

## 5. 操作フロー

1. ユーザーが履歴の右クリックメニューから「ホットキーを割り当てる」を選ぶ。
2. 割当ダイアログが修飾キー＋英数字をキャプチャする。
3. `MainApplication` が候補設定を作成し、`HotkeyRegistrationManager.reconfigure_all()` を呼ぶ。
4. 成功時のみ `pinned_hotkey_bindings` を保存し、履歴一覧を再描画する。対象行のホットキー列には設定したキー組合せが直ちに表示される。失敗時は既存の設定、登録集合、および一覧表示を維持する。
5. ユーザーがホットキーを変更または解除した場合も、成功後に履歴一覧を再描画する。解除後は対象行のホットキー列を空欄にする。
6. Windows のメッセージスレッドがIDを検出し、Tkメインスレッドへ通知する。
7. `MainApplication` は予約IDならウィンドウ表示をトグルする。ピン項目IDなら現在の履歴内容をクリップボードに設定し、通知音を鳴らした後、75ms後に `WindowsPasteSender` でアクティブウィンドウへ `Ctrl+V` を送る。

## 6. 整合性ルール

- 割当はピン留め済みの単一項目に限る。
- ホットキー列は、ピン留め済みかつ有効な割当がある項目にだけキー組合せを表示する。
- ピン解除、個別削除、全履歴削除では対応する割当も解除し、ホットキー列からも直ちに消去する。
- 再ピン留めしても旧割当は復元しない。
- 同一キーを表示/最小化キーまたは別のピン項目へ重複割当できない。
- 起動時に孤立した割当を検出した場合は登録せず、設定を正規化して保存する。
- アプリ終了時は登録済み全IDを解除する。
- 自動貼り付けに失敗しても、クリップボード更新とホットキー登録は維持する。

## 7. Seam と検証

Windows API との seam は `GlobalHotkeyListener` と `WindowsPasteSender` に置く。`HotkeyRegistrationManager` はListenerを注入して、集合検証・ID振り分け・ロールバックを単体で検証できる。GUIは `MainApplication.get_pinned_hotkey_bindings()` と割当/解除 Interface を通じて表示用の状態だけを取得し、Win32の登録詳細や設定の永続化形式を持たない。

検証では、複数IDの振り分け、重複・不正キー・OS競合時の旧集合復元、設定正規化、ピン解除・削除時の解除、既存の表示/最小化ホットキーの回帰に加え、以下を確認する。

- ピン留めかつホットキー設定済みの行に、正規化済みのキー組合せが表示される。
- 通常履歴およびホットキー未設定のピン留め履歴では、ホットキー列が空欄になる。
- 履歴とテーマが同一でも割当だけが変わった場合、対象行のホットキー列が更新される。
- ホットキーの設定、変更、解除、一括解除の成功後に、一覧表示が直ちに更新される。
- クリップボード更新後に `Ctrl+V` のキー押下・解放が送信される。

## 8. 実装順

1. 設定の正規化と複数ホットキー登録基盤を実装する。
2. 起動・終了・発火時のアプリ配線と自動貼り付けアダプターを実装する。
3. 履歴操作と右クリックメニュー、割当ダイアログを接続する。
4. `MainApplication` の表示用割当取得Interfaceと、履歴一覧のホットキー列を接続する。
5. 翻訳と回帰確認を行う。
