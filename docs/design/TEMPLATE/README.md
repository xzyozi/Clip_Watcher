# 設計ドキュメント作成・運用ガイドライン

本ガイドラインは、設計仕様書の作成、命名、参照、および機械可読運用の標準を定めます。別環境や AI エージェント連携でも、一貫した品質と構造を保つために適用します。

## 1. ドキュメント分類とテンプレート

| 分類                   | テンプレート                   | 主な内容                                                             |
| :--------------------- | :----------------------------- | :------------------------------------------------------------------- |
| 基本設計書（BD）       | `TEMPLATE_基本設計書.md`       | 目的、アーキテクチャ方針、コンポーネント分離、システム境界、依存関係 |
| 詳細設計書（DD）       | `TEMPLATE_詳細設計書.md`       | モジュールの入出力 DTO、状態遷移・シーケンス、エラー処理、テスト要件 |
| データ構造仕様書（DS） | `TEMPLATE_データ構造仕様書.md` | 永続化スキーマ、状態分類、配置、原子置換、排他制御                   |

BD、DD、DS は本リポジトリの公式設計テンプレートです。`CLW` は本プロジェクトで用いる接頭辞の例です。BD、DD、DS 以外の文書は、次の軽量なメタデータで目的と正本を表します。

| `document_type`      | 用途                       | 最低限のメタデータ                                |
| :------------------- | :------------------------- | :------------------------------------------------ |
| `operation`          | 運用ルール、手順の正本     | `document_type`、`updated_at`、`canonical_source` |
| `how_to`             | 利用者向け手順・設定例     | `document_type`、`updated_at`、`canonical_source` |
| `archive`            | 履歴的な記録・参考資料     | `document_type`、`updated_at`、`canonical_source` |
| `compatibility_stub` | 移行期の互換性・参照先案内 | `document_type`、`updated_at`、`canonical_source` |

`canonical_source` には正本の設定ファイル、ワークフロー、または参照文書へのリポジトリ相対パスを記載します。BD、DD、DS の詳細属性は、各テンプレートの YAML Frontmatter を正本とします。

## 2. YAML Frontmatter と記法

BD、DD、DS では、文書先頭に `title`、`document_type`、版数、作成日・更新日、作成者、目的、関連文書を含む YAML Frontmatter を置きます。日付は YAML と本文の両方で `YYYY-MM-DD` 形式に統一します。本文直下の表には文書番号、名称、版数、日付、作成者だけを記載し、詳細属性を二重管理しません。

図表は Mermaid を標準とし、全体構造・データフローには `flowchart TD`、状態遷移には `stateDiagram-v2`、対話には `sequenceDiagram`、データ構造には `erDiagram` または `classDiagram` を使います。

## 3. データ境界

| データ種別           | 担当レイヤー                   | 正本 | 定義内容                                   |
| :------------------- | :----------------------------- | :--- | :----------------------------------------- |
| DTO                  | モジュール間・関数間の受け渡し | DD   | 引数、戻り値、イベント、型、検証           |
| DAO / 永続化スキーマ | ストレージ・ファイル保存       | DS   | 物理保存形式、状態分類、原子置換、排他制御 |

## 4. 命名規則

標準形式は `[PROJECT_PREFIX]-[TYPE_CODE]-[NUMBER]_[DOCUMENT_TITLE].md` です。`PROJECT_PREFIX` はプロジェクト識別子、`TYPE_CODE` は `BD`、`DD`、`DS` など、`NUMBER` は 3 桁連番です。BD、DD、DSでは、YAML Frontmatter の `file_name` と本文メタデータ表の **ファイル名** 欄に、実際のリポジトリ相対パスの末尾となるファイル名を同一の値で記載します。各テンプレートの文書番号欄には、この規則に従う値（例: `CLW-BD-001`）を記載します。

## 5. 参照・コード掲載・改訂履歴

特定環境に依存する `file:///...` などの絶対パスは使用せず、文書名またはリポジトリ相対パスで参照します。

**具象ソースコードの掲載禁止は BD、DD、DS にだけ適用します。** これらの設計書では、パラメータ表、型、制約、事前・事後条件、失敗契約、Mermaid 図で仕様を記述します。一方、`how_to` の設定例・操作例、`archive` の歴史的な例、その他の非 BD/DD/DS 文書は、この禁止の対象外です。ただし、秘密情報や環境固有の値は掲載しません。

すべての文書末尾に改訂履歴を置き、変更内容と理由を追跡します。
