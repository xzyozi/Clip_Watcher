# [CW-0078] [bug] クリップボード履歴一覧においてピン留め表示（Pin アイコン / 状態表示）が表示されない・視認できない

## 0. メタ情報 (Scope & Impact)
- **影響範囲**: クリップボード履歴一覧（HistoryListComponent / ttk.Treeview）、アイコン管理（IconManager）、ピン留め表示
- **既存コードへの依存**: あり（`src/gui/components/history_list_component.py`、`src/gui/icon_manager.py`、`src/gui/theme_manager.py`）
- **検出テーマ**: GUIレンダリング・macOS互換性・アクセシビリティ・視認性
- **重要度**: Medium
- **関連Issue**: #212, #196, #203, #204
- **起票ステータス**: `stage:completed`

## 1. 概要・背景
クリップボード履歴一覧ウィジェット（`HistoryListComponent` / `ttk.Treeview`）において、ピン留めされた履歴項目に対してピン留めアイコン（画鋲ピン画像: `pin.png`）やピン留め状態が表示されない、あるいは視認できない事象が報告されている。
特に macOS (Aqua テーマ) 環境や特定のフォント・テーマ設定下において、ピン留めされているかどうかの識別が困難または不可能になる課題が存在する。

### 課題詳細 (Problem Detail)
1. **macOS Aqua テーマにおける Treeview `#0` 列アイコン描画の制約・見切れ**:
   - `HistoryListComponent` は `columns=("hotkey",)` としており、履歴テキストおよびピンアイコンは共に Treeview の `#0`（tree 列）に設定されている（`tree.item(iid, text=..., image=...)`）。
   - macOS の Cocoa ネイティブ描画パイプライン（Aqua テーマ）では、フォントサイズ変更（`tag_configure`）や行の高さ（`rowheight`）、列の左マージン等の影響で、`#0` 列内の画像（16x16px）が左端で見切れる、またはネイティブセルの描画領域外に追いやられて不可視となるケースがある。
2. **選択行におけるピン留め視認性の完全喪失（背景色依存の限界）**:
   - 現在の設計では、ピン留め状態を「`#0` 列の画像」と「`"pinned"` タグによる背景色（`pinned_bg`）」の 2 点で表現している。
   - しかし macOS Aqua 環境では行を選択した瞬間に OS ネイティブの選択アクセントカラー（青やグラファイト等）が行全体に強制適用され、タグの背景色が上書きされる。
   - このとき画像が表示されない（または隠れている）場合、選択中の行がピン留めされているかどうかが画面上から完全に判別不能となる。
3. **独立した「ピン留め (Pin)」列・テキストフォールバックの欠如**:
   - Treeview 上に「Pin」列が存在せず、画像が描画されない・ロードに失敗した場合のフォールバック表現（例: 絵文字 📌 や `[PIN]`、記号 `★` 等）が用意されていないため、画像が非表示になるとピン留め情報が 100% 消失する。
4. **アイコンキャッシュ・再描画タイミングにおける非表示リスク**:
   - Issue #203 でキャッシュ破棄時の世代管理が導入されたが、初期描画時や動的なピン留め・ピン解除操作（`HISTORY_PIN_UNPIN`）の直後において、画像の再バインドが漏れる、または空文字 `""` がセットされたまま残留するケースが残存している可能性がある。

## 2. 仕様および要求事項 (修正方針の検討)
- [x] **案 1 (推奨・独立Pin列の新設または確実な視覚的フォールバックの導入)**:
  1. **ピン留め状態の多層的表示（テキスト/シンボルフォールバック）**:
     - `#0` 列のアイコン画像描画に加え、表示テキスト先頭または専用列において、ピン留め状態を示すシンボル（例: 📌 または `[P]`）を付与できるようにする。
     - 画像描画が正常に行われない環境や高DPI/Retina環境でも、確実にピン留め状態を識別できるようにする。
  2. **独立したピン列（Pin Column）の検討・追加**:
     - Treeview の列構成を `columns=("pin", "hotkey")` とし、ピン状態を独立した列で視覚表示（アイコンまたは記号）することで、行テキストの長さやインデントに左右されない確実な配置を担保する。
  3. **選択状態（Selected State）におけるピン留め明示の維持**:
     - 行が選択中であっても、ピン留め列の表示やテキストインジケータにより、ピン留め状態が OS アクセントカラーに塗りつぶされず視認できるようにする。
  4. **`HistoryListComponent.update_history()` の画像設定ロジック検証・強化**:
     - アイコンマネージャーから画像が取得できなかった場合の安全なフォールバック処理を実装。
- [ ] **案 2 (行の高さ `rowheight` と `#0` 列幅の微調整のみで対応する)**:
  - macOS Aqua の描画挙動に依存し続け、OS のバージョン更新やフォントサイズ変更時に再発する可能性が高いため不採用。

## 5. ドメイン知識・技術上の落とし穴 (Domain Knowledge & Technical Pitfalls)
- **macOS Aqua と Tkinter Treeview の仕様**:
  - `ttk.Treeview` の `#0` 列はツリー階層構造を描画するための特殊列であり、インジケータ（開閉矢印）用スペースが確保される。macOS ではこれがネイティブの開閉三角として扱われるため、リーフノード（子を持たない行）で画像を設定した際に描画オフセットが不自然になる場合がある。
- **データ列（`values`）への画像設定不可**:
  - Tkinter の `ttk.Treeview` はデータ列（`values`）への `PhotoImage` 直接埋め込みに対応していない（画像が指定できるのは `#0` 列の `image=` のみ）。したがってデータ列で表現する場合は Unicode シンボル（📌、★、[P] 等）を用いるか、`#0` 列のレイアウトを最適化する必要がある。

---

## 6. 設計制約・アンチパターンの禁止 (Architecture Constraints & Forbidden Actions)
- **色だけに頼った情報伝達の禁止**: 色覚多様性（アクセシビリティ）および OS の選択ハイライトによる塗りつぶしに対応するため、背景色だけでピン留め状態を表現してはならない。必ず形状（アイコン・記号・テキスト）を併用すること。
- **パフォーマンス劣化の防止**: 履歴行数（100件等）が多い場合でも、スクロール追従性や描画レスポンスを損なわない軽量な表示更新を維持すること。
