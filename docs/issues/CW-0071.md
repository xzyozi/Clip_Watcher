# [CW-0071] [architecture] QuickTaskDialog におけるクリップボード管理・監視レイヤーのバイパスと Tkinter 生 API の直接操作

- **検出テーマ**: 関心事の分離（アーキテクチャ境界）
- **重要度**: Medium
- **関連Issue**: 該当なし
- **起票ステータス**: `stage:ideation` (agys 自律レビュー起票)

## 1. 概要・背景
QuickTaskDialog がクリップボード監視・履歴サービスをバイパスして Tkinter の clipboard_clear() / clipboard_append() を直接呼び出し、アプリ全体のクリップボード状態と整合性を損なっている。

### 課題詳細 (Problem Detail)
QuickTaskDialog._copy_selected において、self.clipboard_clear() および self.clipboard_append(content) を使用してシステムクリップボードを直接書き換えている。本アプリケーションにはクリップボードの変更監視、履歴蓄積、安全コピー検証、通知などを統合管理する ClipboardMonitor や HistoryService（app.monitor.update_clipboard(...)）が存在しているにもかかわらず、ダイアログが下位の Tkinter / OS レベルの生 API を直接叩くことで上位のビジネスルール・監視層をバイパスしている。これにより、クイックタスクからコピーした内容が履歴や Undo/Redo、通知機能に正しく連携されず、また UI 単体テスト時にクリップボード処理のモック検証を困難にしている。
