# [CW-0034] [保留] TextWorkflowの別配布物化と外部プラグイン登録方式を検討する

## 概要
TextWorkflowを別配布可能なモジュールとして切り出す必要性と、外部プラグインの発見・登録・互換性判定方式を検討する。

## 背景
TextWorkflowには公開Interface、設定・履歴・UI通知のseam、ReDoS対策が整備されている。ただし、外部利用者・独立配布・プラグイン提供者の要件はまだ確定していないため、現時点での別パッケージ化は保留とする。

現在の `PluginManager` は内蔵パッケージを反射的に探索し、無引数で生成する方式である。外部配布プラグインの発見、依存性注入、API互換性判定には対応していない。

## 前提条件（未充足のため保留）
- [ ] TextWorkflowの外部利用者・利用シナリオが定義されている
- [ ] #94 で公開パッケージ名と互換性方針が確定している
- [ ] #95 で配布物ビルド・インストール・CLI検証が確立している
- [ ] 外部プラグインを許可するか、許可する場合の信頼境界が決定している

## 検討事項
- TextWorkflowを同一配布物内のモジュールとして維持するか、独立パッケージ化するか
- 外部プラグインの発見方式（entry points、明示登録、設定ファイル等）
- 依存性注入・設定・履歴・イベント通知の公開範囲
- APIバージョン・互換性判定・廃止ポリシー
- 外部プラグインの安全性・例外隔離・権限境界

## 完了条件
- 別配布物化の要否が根拠とともに決定されている
- 外部プラグインを提供する場合の登録・互換性・安全性方針が文書化されている
- 実装が必要な場合は、独立したrequirements/design/tasksへ分割されている
