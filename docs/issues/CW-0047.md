# [CW-0047] [security] database_manager における旧履歴JSON移行時のパストラバーサル未検証および安全でないバックアップファイル置換

## 0. メタ情報 (Scope & Impact)
- **検出テーマ**: セキュリティ
- **重要度**: High
- **関連Issue**: 該当なし
- **起票ステータス**: `stage:ideation` (agys 自律レビュー起票)

## 1. 概要・背景
旧履歴JSONからの移行処理においてパス検証が欠落しており、さらにバックアップ時のTOCTOU競合と既存ファイル削除による任意ファイル削除・上書きリスクが存在する。

### 課題詳細 (Problem Detail)
check_and_migrate_json では引数 history_file_path に対するパストラバーサル検証（パスの正規化、ベースディレクトリ境界チェック、シンボリックリンク検証）が行われておらず、外部設定等から不正なパスやUNCパスが渡された場合に予期せぬファイル操作やNTLM漏洩を招く恐れがあります。さらに、データ移行完了後に backup_path = history_file_path + '.bak' を作成する際、os.path.exists の確認から os.remove、shutil.move に至る処理がアトミックに行われておらず、典型的な TOCTOU（Time-of-Check to Time-of-Use）競合状態が存在します。シンボリックリンクやジャンクションを悪用した任意ファイル削除（Arbitrary File Deletion）や意図しない既存バックアップの上書き破壊につながる危険性があります。
