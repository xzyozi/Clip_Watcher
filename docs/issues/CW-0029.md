# [CW-0029] SQLite接続がクローズされておらず、テスト間でDBファイルが汚染される

### 概要
`tests/test_history_service.py` の6テストが失敗する。前のテストで追加した履歴データが次のテストに残っており、テスト分離ができていない。

### 再現手順
```powershell
python -m pytest tests\test_history_service.py -v
```

### 期待される結果
各テストは `db_manager` フィクスチャが生成する空のDBから開始し、他テストの影響を受けない。

### 実際の結果
```
AssertionError: assert 4 == 2
 +  where 4 = len([('Item 2', False, 4.0), ('Item 1', False, 3.0), ('Normal 2', False, 2.0), ('Normal 1', False, 1.0)])
```
前のテスト（`test_initial_history_is_empty`など）で作成した `Normal 1` / `Normal 2` が残ったまま次のテストに引き継がれている。

### 根本原因
`sqlite3.Connection` を `with` 文で使った場合、Pythonの仕様として **トランザクションのコミット/ロールバックのみ**が行われ、接続自体はクローズされない。

```python
# src/db/dao/base_dao.py
def execute_write(self, query: str, params: tuple[Any, ...] = ()) -> int:
    with self._lock:
        with self._get_connection() as conn:   # ← close() されない
            cursor = conn.cursor()
            cursor.execute(query, params)
            conn.commit()
            return cursor.lastrowid or cursor.rowcount
```

`database_manager.py` の `_initialize_tables()` も同様。Windows環境では接続が開いたままだとファイルハンドルが解放されず、`tests/conftest.py` のクリーンアップ処理

```python
if os.path.exists(db_path):
    try:
        os.remove(db_path)
    except Exception:
        pass  # ← 削除失敗を握りつぶしている
```

が `PermissionError` で失敗し、例外が握りつぶされて次のテストに古いDBファイルが引き継がれる。

### 修正案
`_get_connection()` を呼ぶ全箇所で明示的に `conn.close()` するか、`try/finally` で確実にクローズする。

```python
def execute_write(self, query: str, params: tuple[Any, ...] = ()) -> int:
    with self._lock:
        conn = self._get_connection()
        try:
            cursor = conn.cursor()
            cursor.execute(query, params)
            conn.commit()
            return cursor.lastrowid or cursor.rowcount
        finally:
            conn.close()
```

`base_dao.py`, `database_manager.py` の該当箇所すべてに同様の対応が必要（他DAOも `_get_connection()` を直接呼ぶ箇所があれば同様）。
