# [CW-0070] [architecture] SettingsWindow._validate_pending_values における検証フェーズとインフラ副作用（ホットキー再登録）の混同

## 0. メタ情報 (Scope & Impact)
- **検出テーマ**: 関心事の分離（アーキテクチャ境界）
- **重要度**: Medium
- **関連Issue**: 該当なし
- **起票ステータス**: `stage:ideation` (agys 自律レビュー起票)

## 1. 概要・背景
設定ダイアログのバリデーションメソッドが、入力検証の責務を逸脱して OS ホットキー再登録というインフラ層への副作用を即時実行している。

### 課題詳細 (Problem Detail)
SettingsWindow._validate_pending_values は、ユーザーが入力した設定値が妥当か検証するためのフックである。しかし、このメソッド内で hrm.reconfigure(enabled, combo) が呼び出され、OS に対するグローバルホットキーの実際の登録・解除（Win32 API 呼び出しを伴うインフラ副作用）が実行されている。設定の確定（保存/適用）前である検証フェーズで副作用が実行されるため、後続の別フィールドの検証が失敗した場合や、設定ファイルの保存エラーが発生した場合でも、OS 上のホットキー設定だけが先行して変更されてしまい、永続化された設定ファイルと実際の実行時状態に不整合が生じる。
