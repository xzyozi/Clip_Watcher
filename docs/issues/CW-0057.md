# [CW-0057] [security] JSONFormatterPlugin における入力サイズおよび再帰深度・巨大整数バリデーション欠落によるDoSとクラッシュ

## 0. メタ情報 (Scope & Impact)
- **検出テーマ**: セキュリティ
- **重要度**: Medium
- **関連Issue**: 該当なし
- **起票ステータス**: `stage:ideation` (agys 自律レビュー起票)

## 1. 概要・背景
入力サイズ未検証によるメモリ枯渇DoS、および深くネストされた構造（RecursionError）や巨大整数（ValueError）による未捕捉例外クラッシュのリスクがあります。

### 課題詳細 (Problem Detail)
JSONFormatterPlugin.process() では、渡されたテキストのサイズ上限チェックを一切行わずに json.loads(text) および json.dumps(..., indent=4) を実行します。大容量 JSON に対するインデント展開は著しいメモリ消費と CPU スパイクを引き起こし、メインスレッドをブロックします。さらに、深くネストされたブラケット構造（[[[[...]]]] など）が入力された場合に発生する RecursionError（RuntimeError の派生）、および Python 3.11+ の整数文字列表現制限（CVE-2020-10735、4,300桁超過）で発生する ValueError（JSONDecodeError の親クラス）が例外ハンドラ except (json.JSONDecodeError, TypeError): で捕捉されません。そのため、細工されたテキストが渡されると未捕捉例外が発生し、フォーマット処理および履歴更新処理が異常終了します。
