# [CW-0054] [edge_cases] history_dao および meta_phrase_dao における created_at 破損レコードによる一覧取得全体のフェイル

## 0. メタ情報 (Scope & Impact)
- **検出テーマ**: エッジケース処理
- **重要度**: Medium
- **関連Issue**: 該当なし
- **起票ステータス**: `stage:ideation` (agys 自律レビュー起票)

## 1. 概要・背景
get_items や get_by_category で `created_at=float(row[4])` を一括内包表記で実行しているため、1件でも NULL や不正値が混入すると例外により全レコードが空リストとして返され、全履歴・定型文が表示不能になる。

### 課題詳細 (Problem Detail)
ClipboardHistoryDAO.get_items および MetaPhraseDAO.get_by_category では、SELECT クエリで取得した全行に対して `[ClipboardHistoryDTO(..., created_at=float(row[4])) for row in rows]` のようにリスト内包表記で変換を行っている。データベースに過去の移行データや外部要因によって created_at が NULL、空文字、または破損した非数値文字列となっているレコードが単一でも含まれていた場合、`float(row[4])` で TypeError または ValueError が発生する。メソッド全体が `try...except Exception as e:` で囲まれているため、例外発生時は logger.error を出力した上で `return []`（空リスト）が返却される。この結果、データベース内に何千件もの正常な履歴が存在していたとしても、たった1件の破損レコードがあるだけで UI 上の履歴一覧や定型文一覧が完全に空になり、ユーザーから見るとデータが全消失したように見える。
