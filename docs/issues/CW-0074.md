# [CW-0074] [bug] 設定でフォントサイズを変更してもクリップボード履歴一覧に反映されない（macOS / ttk.Treeview のスタイルおよび行の高さ未追従）

## 0. メタ情報 (Scope & Impact)
- **影響範囲**: クリップボード履歴一覧ウィジェット（HistoryListComponent）およびフォント設定適用
- **既存コードへの依存**: あり（`src/gui/components/history_list_component.py` のフォント適用およびタグ処理を改修）
- **検出テーマ**: GUIレンダリング・フォント設定・macOS互換性
- **重要度**: Medium
- **関連Issue**: #195
- **起票ステータス**: `stage:ready`

## 1. 概要・背景
設定画面（`SettingsWindow`）の「Font」タブにおいて、「History Font」のフォントサイズ（`history_font_size`）を変更して「Apply」または「Save」を実行しても、メイン画面のクリップボード履歴一覧（`HistoryListComponent` / `ttk.Treeview`）のフォントサイズが視覚的に反映されない。
特に macOS（Aqua テーマ）環境においてフォントサイズが全く変わらない事象が確認されている。

### 課題詳細 (Problem Detail)
1. **macOS (Aqua テーマ) における `ttk.Style().configure("Treeview", font=...)` の不動作（主因）**:
   - macOS の Tkinter (Tk 8.6) では Cocoa ネイティブの `aqua` テーマが使用される。
   - `aqua` テーマの `ttk.Treeview` はネイティブのセル描画ルーチンを使用しているため、`ttk.Style().configure("Treeview", font=...)` によるスタイル変更がネイティブコントロール側で無視・オーバーライドされ、フォントサイズ変更が反映されない。
   - 一方で、`tree.tag_configure("tag_name", font=...)` を介してアイテムタグにフォントを指定すると、macOS Aqua 環境でも各行にフォントが適用される。
   - しかし現在の `HistoryListComponent` では：
     - 未ピン留めの通常行にはタグが一切付与されていない（`tags = ()`）。
     - ピン留め行には `"pinned"` タグが付与されているが、`tag_configure("pinned", background=...)` のみで `font` は指定されていない。
     - その結果、どの行にもフォント設定が届かない。
2. **`ttk.Treeview` の行の高さ（`rowheight`）が固定されたまま更新されない**:
   - `ttk.Treeview` は、フォントサイズが変更されても行の高さ（`rowheight`）を自動的に再計算しない。
   - 現在の `apply_font()` は `style.configure("Treeview", font=font)` のみを行っており、`rowheight` を更新していないため、デフォルトの行の高さ（約18〜20px）のまま固定される。
   - その結果、フォントサイズを大きくしても行の高さが広がらず、テキストが上下に切れて見切れたり、行同士が重なって表示崩れを引き起こす。
3. **テーマ切替時・履歴更新時のフォント再適用漏れ**:
   - テーマ切替時（`ThemeManager.apply_theme`）や履歴再描画時（`update_history`）に、タグやスタイル上のフォント状態が失われたり再適用されず初期状態に戻る可能性がある。

## 2. 仕様および要求事項 (修正方針の検討)
- [x] **案 1 (推奨・最小限かつ堅牢なアプローチ)**:
  1. **タグ構成の拡充**:
     - `HistoryListComponent` の全履歴行に対し、基本タグ（例: `"history_item"`）を付与する。
     - ピン留め行は `("history_item", "pinned")`、通常行は `("history_item",)` とする。
  2. **`apply_font` の改修**:
     - フォントの行間メトリクス（`font.metrics("linespace")` またはフォントサイズに応じた安全な計算値）に基づき、適切な `rowheight` を計算して `style.configure("Treeview", font=font, rowheight=calculated_rowheight)` を設定する。
     - macOS (Aqua) 対応として、タグ `history_item`（および必要に応じて `pinned`）に対して `self.tree.tag_configure("history_item", font=font)` を設定する。
     - 適用されたフォント（`self.current_font`）をコンポーネント内で保持する。
  3. **履歴更新・テーマ切替時のフォント維持**:
     - `update_history()` で新規行・既存行のタグ付与に `"history_item"` を含め、タグ設定（`tag_configure`）が確実に全行へ波及するようにする。
     - テーマ切替（`apply_theme`）時にも保持しているフォントが維持されるようにする。
- [ ] **案 2 (全体フォント nametofont("TkDefaultFont") の一括書き換え)**:
  - `font.nametofont("TkDefaultFont")` を更新するアプローチ。
  - しかし、メイン画面のクリップボード詳細テキストエリアやメニュー、ボタンなど、本来独立しているべき他のウィジェットのフォントサイズまで一括で変更されてしまい、UI全体のレイアウト崩れと責務分離違反を招くため不採用。

## 5. ドメイン知識・技術上の落とし穴 (Domain Knowledge & Technical Pitfalls)
- **macOS Aqua と ttk.Treeview のフォント挙動**:
  - Tkinter on macOS の `aqua` テーマでは、`style.configure("Treeview", font=...)` がネイティブ描画パイプラインによって無視される制約がある。`tree.tag_configure(tag, font=...)` を利用してアイテムタグ単位でフォントを指定することが Aqua における確実なフォント反映手段である。
- **Treeview の rowheight 自動調整の欠如**:
  - `ttk.Treeview` はフォントサイズを変更しても行の高さ（`rowheight`）を自動調整しない。`font.metrics("linespace")`（またはフォントサイズ + 上下パディング約6〜8px）を計算して `style.configure("Treeview", rowheight=...)` に設定する必要がある。
- **タグの順序と優先度**:
  - `Treeview` のタグはリストの先頭から順に評価されるため、ピン留め行の背景色（`"pinned"`）と基本フォント（`"history_item"`）が競合しないよう、`tags=("history_item", "pinned")` または相互に干渉しない属性のみを設定する。

## 6. 設計制約・アンチパターンの禁止 (Architecture Constraints & Forbidden Actions)
- **グローバルフォント変更の禁止**: `TkDefaultFont` などのグローバル名前付きフォントを書き換えて全体に波及させてはならない。影響範囲は `HistoryListComponent`（および設定された履歴一覧）に閉じること。
- **テーマ制御の一貫性**: `ThemeManager` が管理する背景色・選択色マッピングを破壊しないこと。

---

## 7. 対象外 (Non-Goals)
- クリップボード詳細テキストエリア（`clipboard_text_widget`）のフォント変更（すでに `clipboard_text_widget.config(font=...)` で正常に動作しているため対象外）。
- メタデータ管理ウィンドウなど、他画面の Treeview に対するフォントサイズ連動（本件はメイン画面のクリップボード履歴一覧を対象とする）。
