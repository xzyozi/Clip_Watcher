# [CW-0074] [feat] macOS環境におけるログイン時自動起動（スタートアップ）登録機能の実装とプラットフォーム抽象化

## 0. メタ情報 (Scope & Impact)
- **検出テーマ**: プラットフォーム互換性・OS統合（macOS）
- **重要度**: Medium
- **関連Issue**: #155
- **関連詳細設計書**: [CLW-BD-001_ClipWatcher全体アーキテクチャ基本設計書.md](../design/CLW-BD-001_ClipWatcher全体アーキテクチャ基本設計書.md)
- **起票ステータス**: `stage:ideation`

## 1. 概要・背景
現在、Clip Watcher の設定項目 `startup_on_boot`（OS起動時の自動起動）における登録・解除処理（`src/core/app_main.py: _manage_startup`）は Windows 環境（`sys.platform == "win32"`）のみを対象として実装されています（`%APPDATA%\Microsoft\Windows\Start Menu\Programs\Startup\ClipWatcher.bat` の生成／削除）。

macOS（`sys.platform == "darwin"`）環境においては、以下のとおり自動起動（スタートアップ）登録機能が存在せず、設定UIにも不整合があります。

1. **macOS 向け自動起動処理の欠落**:
   - `_manage_startup()` 内で `if sys.platform == "win32":` のみが記述されており、macOS 環境では設定を有効化しても何ら処理が行われずスキップされます。
2. **設定画面 UI ラベルの Windows 固定**:
   - `src/core/config/settings_manager.py` におけるスキーマのラベルが `"Start with Windows"` と固定されており、macOS 上でもそのまま表示されています。
3. **OS依存コードのプラットフォーム分離未実施**:
   - #148（プラットフォーム抽象化）にてホットキーやプロセス監視、二重起動排他制御のプロトコル分離が進められていますが、スタートアップ管理（自動起動登録）のプロトコルは未定義であり、`MainApplication` 内にベタ書きされています。

---

## 2. 課題詳細 (Problem Detail)

- **ユーザー体験の阻害**:
  macOS ユーザーが設定画面で自動起動を有効にしても次回ログイン時にアプリが起動しないため、期待通りの動作になりません。
- **UI表示の不自然さ**:
  macOS 環境下で「Start with Windows」と表示されるため、OS プラットフォームに適した表現（例: "Start at Login" や "OS起動時に実行"）への適応が必要です。
- **アーキテクチャの統一性**:
  Windows 側のスタートアップ処理にはセキュリティ課題（#110 / CW-0039: .bat へのパス埋め込みインジェクション等）も存在しており、各プラットフォームのアダプター層へ委譲するリファクタリングが望まれます。

---

## 3. 仕様および解決方針 (Proposed Solution)

### 3.1 プラットフォーム抽象インターフェースの新設
`src/core/platform/protocols.py` にスタートアップ管理用プロトコル（例: `StartupController`）を追加します。

```python
class StartupController(Protocol):
    def is_enabled(self) -> bool: ...
    def enable(self) -> bool: ...
    def disable(self) -> bool: ...
```

### 3.2 macOS 向け具象実装 (`LaunchAgents` plist 方式)
- ユーザーログイン時の自動起動標準である `~/Library/LaunchAgents/com.clipwatcher.app.plist` を管理。
- 実行中の Python インタプリタ（`sys.executable`）と `clip_watcher.py` の絶対パスを指定した `ProgramArguments` を構成。
- `RunAtLoad: true`, `ProcessType: Interactive` 等を設定。
- 無効化時は plist ファイルを安全に削除（または `launchctl bootout/unload`）。

### 3.3 Windows 実装の移行 & Null 実装
- Windows 実装は `src/core/platform/windows/startup.py` へ移動（CW-0039 と連携しショートカット `.lnk` またはレジストリ登録へ移行）。
- Linux / 未対応環境向けには `src/core/platform/null/startup.py`（No-Op）を提供。

### 3.4 設定画面 UI ラベルの動的適応 / i18n
- プラットフォームに応じたラベル表示（Windows: "Start with Windows", macOS: "Start at Login", Linux/その他: "Start on System Boot"）または汎用的な表記へ改善。
