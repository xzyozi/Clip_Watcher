# [CW-0077] [bug] macOS 環境での python3 起動エラー（Python 3.9 実行時の型ユニオン記法エラーおよび早期バージョンチェック機構の欠如）

## 0. メタ情報 (Scope & Impact)
- **影響範囲**: アプリケーション起動プロセス（エントリーポイント `clip_watcher.py`、初期化フロー `src/event_handlers/__init__.py`）
- **既存コードへの依存**: あり（`clip_watcher.py`、`src/event_handlers/__init__.py`、`src/core/events/event_dispatcher.py` 等）
- **検出テーマ**: macOS互換性・起動処理・実行環境バリデーション
- **重要度**: High（macOS標準環境でアプリが起動せず即座にクラッシュする）
- **関連Issue**: #211
- **起票ステータス**: `stage:completed`

## 1. 概要・背景
macOS の標準ターミナルにおいて `python3 clip_watcher.py` を実行すると、アプリケーションが起動せず即座に以下の `TypeError` を出力してクラッシュする事象が確認された。

### 課題詳細 (Problem Detail)
1. **macOS システム標準 Python (Python 3.9) と PEP 604 型ユニオン構文の非互換性**:
   - macOS の Xcode Command Line Tools に同梱されるシステム標準 `/usr/bin/python3` は Python 3.9.6 であることが多い。
   - `pyproject.toml` 上は `requires-python = ">=3.10"` と指定されているが、`python3` コマンドで起動した場合にシステム Python が優先実行される。
   - PEP 604 の `A | B`（型ユニオン構文）は Python 3.10 以降でビルトインサポートされた機能であり、`from __future__ import annotations` がないモジュール（例: `src/core/events/event_dispatcher.py` 等）ではクラス定義時に評価され、`TypeError: unsupported operand type(s) for |` でクラッシュする。
2. **バージョンチェック機構の配置不備（デッドコード化）**:
   - `src/event_handlers/__init__.py` の 185 行目に `if sys.version_info < (3, 10):` という警告チェックが存在するが、この関数が実行される前のモジュール import 段階（`from src.event_handlers import start_app`）でクラッシュするため、チェック処理に絶対に到達できない。
3. **ユーザーフレンドリーなエラー案内・起動ガイダンスの欠如**:
   - エントリーポイント `clip_watcher.py` の最上部にバージョンガードが存在しないため、利用者は「なぜ動かないのか」「どうすれば解決するのか（仮想環境 `.venv` のアクティベートが必要等）」が分からず、不可解なトレースバックのみを提示される。

## 2. 仕様および要求事項 (修正方針の検討)
- [x] **案 1 (推奨・早期バージョンチェックと多層的フェイルセーフの導入)**:
  1. **`clip_watcher.py` 最上部での早期 Python バージョンチェック**:
     - 内部パッケージ（`src` 配下）の import より前に `sys.version_info < (3, 10)` を即座に判定。
     - 条件を満たさない場合は、stderr 出力および GUI 環境向けのアラート（macOS では `osascript`、または安全な Tkinter 単体ダイアログ）で「Python 3.10 以上が必要です。現在のバージョン: {sys.version}。仮想環境 (.venv) をアクティベートして実行してください」と明示して `sys.exit(1)` で安全に終了する。
  2. **全モジュールへの `from __future__ import annotations` 徹底**:
     - `src/core/events/` を含む `|` 記法を使用するソースコードに `from __future__ import annotations` を適用し、型評価タイミングによる不意の構文・実行時エラーを防止する。
  3. **起動ドキュメント・ガイダンスの充実**:
     - macOS 環境における推奨起動手順（`.venv/bin/python clip_watcher.py` または `source .venv/bin/activate && python3 clip_watcher.py`）を README に明記する。
- [ ] **案 2 (コード全体を Python 3.9 互換にダウングレードする)**:
  - `typing.Union` や `typing.Optional` へ書き換えて Python 3.9 での動作を可能にする。
  - しかしプロジェクト全体の型設計規約（Python >= 3.10 前提）と乖離し、今後のメンテナンスコストが増大するため不採用。

## 5. ドメイン知識・技術上の落とし穴 (Domain Knowledge & Technical Pitfalls)
- **import 順序の重要性**:
  - Python では `from X import Y` を実行した時点で対象モジュールおよびその依存先がすべて読み込まれてトップレベルの式が評価される。したがってバージョンチェックは `clip_watcher.py` の 1 行目（標準ライブラリ `sys` のみを使用）で行わなければならない。
- **GUI ダイアログの依存関係**:
  - バージョン不適合時に `tkinter.messagebox` を呼び出すと、Tkinter 自体の初期化失敗（ヘッドレス環境や Tk 8.5 競合等）で二次例外が起きる可能性がある。macOS では `osascript -e 'display alert ...'` をフォールバックとして併用すると最も安全である。

## 6. 設計制約・アンチパターンの禁止 (Architecture Constraints & Forbidden Actions)
- **無関係な依存の追加禁止**: バージョンチェックのために外部ライブラリを導入してはならない。標準ライブラリ（`sys`）のみで完結させること。
- **サイレント終了の禁止**: バージョンが満たされない場合に何も出力せず異常終了してはならない。必ずユーザーに次のアクション（Python 3.10+ の導入や仮想環境の起動）を提示すること。
