# [CW-0040] [security] config_resolver における workspace_root の未検証パス解決によるNTLM漏洩および設定改変リスク

## 0. メタ情報 (Scope & Impact)
- **検出テーマ**: セキュリティ
- **重要度**: Medium
- **関連Issue**: 該当なし
- **起票ステータス**: `stage:ideation` (agys 自律レビュー起票)

## 1. 概要・背景
外部から指定可能な workspace_root に対してパストラバーサルやUNCパスの検証が行われておらず、NTLMハッシュの外部流出やセキュリティ制限の強制無効化が可能となっている。

### 課題詳細 (Problem Detail)
ConfigurationResolver.resolve では、WorkflowRequest.workspace_root が指定された際に os.path.join(workspace_root, ".clipwatcher", "workflow.json") をそのまま open して読み込みます。workspace_root がリモートUNCパス（例: \\attacker\share）の場合、ファイルアクセス時に Windows の NTLM 認証が自動発生し、NetNTLM ハッシュが外部サーバに漏洩する脆弱性があります。また、読み込まれた設定は deep_overlay で無制限にマージされるため、悪意あるワークスペース設定によって ReDoS 対策の上限（classifierRegexTimeoutSeconds や classifierRegexMaxPatternLength）や入力上限（maxInputBytes）が極端な値へ書き換えられ、セキュリティ機構が無効化される恐れがあります。
