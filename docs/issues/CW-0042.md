# [CW-0042] [edge_cases] classifier における正規表現子プロセス異常終了（EOF/切断）時の EOFError 未捕捉によるアプリクラッシュ

## 0. メタ情報 (Scope & Impact)
- **検出テーマ**: エッジケース処理
- **重要度**: High
- **関連Issue**: 該当なし
- **起票ステータス**: `stage:ideation` (agys 自律レビュー起票)

## 1. 概要・背景
正規表現評価用の子プロセスがOOMや外部要因で異常終了した場合、パイプ切断により poll() が True を返した後の recv() で EOFError が発生し捕捉されずにクラッシュする。

### 課題詳細 (Problem Detail)
ReDoS対策として multiprocessing.Process を使用し、親プロセスと子プロセスの間を Pipe で接続して結果を受信しています。子プロセスが OOM（メモリ不足）や強制終了（SIGKILLなど）により異常終了した場合、パイプの接続が切断されます。multiprocessing.connection の仕様上、パイプが相手側から切断・クローズされた状態でも poll() は True を返します。その直後に result_receiver.recv() を実行すると EOFError が送出されますが、_evaluate_regex_safely 内では EOFError を捕捉していないため、未処理例外としてメインアプリケーションがクラッシュします。
