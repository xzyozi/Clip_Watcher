# [CW-0025] 簡易レビュー

現行 src/ 簡易レビュー
Git差分ではなく、現在の実装を ruff.toml / mypy.ini と設計仕様書に照らして静的確認しました。コード変更・テスト実行はしていません。

Standards（規約）
高 — 設定ファイルがJSONとして正しくても、起動時に落ちる可能性
settings_manager.py 26
 は json.load() の結果を検証せず辞書へキャストしています。たとえば settings.json が null や文字列の場合、self.settings.update(...) で例外になります。
対応: dict かどうか、キーと値の型・範囲を検証してから取り込むようにします。

中 — EventDispatcherの型定義と実際の使い方が不一致
event_dispatcher.py 17-54
 はリスナーを「引数1つ」と型定義しつつ、実際には引数なし・複数引数で呼んでいます。各所の # type: ignore により、mypyでイベント契約の不整合を検出できません。
対応: イベントごとのペイロード型を定義するか、少なくとも型定義を実際のシグネチャに合わせます。

Spec（仕様・設計との整合）
高 — 検索結果で選んだ履歴とは別の項目を編集・コピーする恐れ
src/gui/main_gui.py:82, 154, 237, 267, 279
検索時は filtered_history を表示していますが、選択位置から実データを引く際は未検索の self.history_data[index] を使っています。またコピー操作はリストの位置を送っているのに、ハンドラ側は履歴IDとして扱っています。
対応: 表示中の履歴リストまたはIDを一貫して利用し、位置（index）をイベント境界の外へ渡さないようにします。

高 — 選択した履歴へのプラグイン変換が失敗する
history_handlers.py 211

history_component.history を参照していますが、コンポーネントが持つ属性は displayed_history です。そのため、選択項目へのフォーマット適用時に AttributeError になる可能性が高いです。
対応: 表示中データを正しい属性から取得するか、選択位置をIDへ変換してサービス層から対象履歴を取得します。

中 — クリップボード監視スレッドの設計書との不整合
clipboard_monitor.py 121

設計書は「監視スレッドがGUIを直接操作せず、イベント経由でメインスレッドに更新を任せる」方針ですが、実装はワーカースレッドから tk_root.after(...) を呼んでいます。Tkinterのスレッド境界が曖昧になり、終了時や負荷時に不安定化するリスクがあります。
対応: 監視を after のメインスレッドループへ統一するか、ワーカーの結果をキュー経由でメインスレッドが処理する構造にします。

要約
最優先: 検索中のコピー・編集対象がずれる問題と、プラグイン変換時の属性参照エラー。いずれもユーザー操作で直接不具合になります。
次点: 設定JSONの検証と、Tkinterのスレッド境界の整理。
