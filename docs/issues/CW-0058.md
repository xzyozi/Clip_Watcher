# [CW-0058] [security] UnitConverterComponent におけるタイムスタンプ入力範囲の未検証およびプラットフォーム例外（OSError/OverflowError）未捕捉によるクラッシュ

## 1. 概要・背景
Unix タイムスタンプ変換時に負値やミリ秒エポック値などの範囲外入力で OSError や OverflowError が発生し、例外未捕捉により GUI がクラッシュします。

### 課題詳細 (Problem Detail)
UnitConverterComponent では、入力欄の <KeyRelease> イベントに応じて _convert() および _convert_time() が即座に呼び出されます。from_unit == 'Unix Timestamp' の場合、ts = float(input_str) の後 datetime.fromtimestamp(ts) が実行されます。Windows 環境の C ランタイムでは、1970年以前の負のタイムスタンプや、プラットフォームの time_t 上限を超える値（ミリ秒単位の 13 桁タイムスタンプ 1700000000000 など）に対して ValueError ではなく OSError: [Errno 22] Invalid argument や OverflowError を送出します。しかし、本メソッドの例外ハンドラは except (ValueError, TypeError) as e: のみであり、OSError および OverflowError が捕捉されないため、外部テキストから一般的なエポックミリ秒を貼り付けた瞬間に未処理例外が Tkinter イベントループに波及してクラッシュします。また、単位変換における 1e308 等の極大値入力時にも OverflowError: float overflow が未捕捉となります。
