# [CW-0050] [security] history_dao の cleanup_old における入力値未検証および動的プレースホルダ展開によるDoS・変数上限超過エラー

- **重要度**: Low
- **関連Issue**: 該当なし
- **起票ステータス**: `stage:ideation` (agys 自律レビュー起票)

## 1. 概要・背景
履歴クリーンアップ処理において limit の負値未検証と、SQLiteバインド変数上限を超える可能性のある動的プレースホルダ展開が存在する。

### 課題詳細 (Problem Detail)
ClipboardHistoryDAO.cleanup_old(limit) では、引数 limit に対する非負値バリデーションが存在せず、誤って負値（例: -1）が渡された場合に excess が不正に肥大化して未ピン留め履歴が一括全削除される危険があります。さらに、超過削除対象のID群をすべてメモリに取得した上で placeholders = ','.join('?' for _ in ids_to_delete) により単一クエリの IN (?) 句に展開しています。超過件数が大量にある場合、SQLiteのバインド変数上限（最大32,766個、旧バージョンでは999個）を超過して sqlite3.OperationalError が発生し、クリーンアップ処理が失敗し続けてDBが肥大化し続ける（リソース枯渇）リスクがあります。
