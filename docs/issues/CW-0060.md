# [CW-0060] [security] ScheduleHelperComponent における時刻入力値（時・分）の範囲バリデーション欠落とdatetime.replaceの未捕捉例外

## 0. メタ情報 (Scope & Impact)
- **検出テーマ**: セキュリティ
- **重要度**: Low
- **関連Issue**: 該当なし
- **起票ステータス**: `stage:ideation` (agys 自律レビュー起票)

## 1. 概要・背景
時間・分 Combobox の自由入力に対する数値範囲検証が欠落しており、範囲外値による datetime.replace の未捕捉 ValueError でクラッシュします。

### 課題詳細 (Problem Detail)
ScheduleHelperComponent の hour_combo および minute_combo には state='readonly' が指定されておらず、ユーザーが任意の文字列・数値を手動入力できます。_select_date(day) では int(self.hour_var.get()) の型変換のみが try...except ValueError で囲まれていますが、得られた hour と minute が有効な時刻範囲（0 <= hour <= 23, 0 <= minute <= 59）に収まっているかの検証が欠落しています。さらに、その直後の new_date_with_time = new_date_for_check.replace(hour=hour, minute=minute) は try...except の外側で実行されるため、24 以上の値や負値（例: 25, 99, -1）が入力された状態でカレンダーをクリックすると ValueError: hour must be in 0..23 が未捕捉のまま送出され、GUI イベントハンドラがクラッシュします。
