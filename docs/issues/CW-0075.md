# [CW-0075] [bug] macOS (Aqua) 環境における Treeview の配色制御とピン留め・選択状態の視認性維持

## 0. メタ情報 (Scope & Impact)
- **影響範囲**: クリップボード履歴一覧（HistoryListComponent）のテーマ配色、選択状態、ピン留め行表示
- **既存コードへの依存**: あり（`src/gui/theme_manager.py` および `src/gui/components/history_list_component.py`）
- **検出テーマ**: macOS互換性・テーマ制御・アクセシビリティ
- **重要度**: Medium
- **関連Issue**: #196
- **起票ステータス**: `stage:ready`

## 1. 概要・背景
macOS 環境において Tkinter はネイティブ Cocoa レンダリングを行う `aqua` テーマを採用しているが、`aqua` テーマの `ttk.Treeview` は Apple の Human Interface Guidelines（HIG）に準拠したネイティブ描画パイプラインを強制するため、アプリ側のテーマ配色（Dark / Light）やピン留め表示において以下の視認性低下・配色不整合が発生する。

### 課題詳細 (Problem Detail)
1. **Treeview 背景色（`background` / `fieldbackground`）の上書き不可**:
   - `src/gui/theme_manager.py` で `style.configure("Treeview", background=..., fieldbackground=...)` を設定しても、macOS Aqua では OS ネイティブの背景（ライト/ダーク外観や交互ストライプ）が優先され、アプリ定義の色が無視される。
   - アプリ側が Dark テーマ設定時、テキスト色（`foreground`）のみが白・明るいグレーに設定され、背景が OS のライト外観のままだと文字が白飛びして不可視となるリスクがある。
2. **選択行ハイライトによるピン留め背景色の消失**:
   - macOS Aqua では、アイテム選択時のハイライト背景色が OS システム設定の「アクセントカラー」（青、紫、グラファイト等）で強制描画される。
   - このため、ピン留め行（`"pinned"` タグ）が選択された際、タグで設定したピン留め背景色（`pinned_bg`）が完全に上書きされ、選択中はその行がピン留めされているかどうかが背景色から判別不能になる。
3. **列見出し（`Treeview.Heading`）の配色追従の制限**:
   - 列見出しはネイティブボタン風アピアランスで描画されるため、背景色変更や高さ調整が効かず、テーマ切り替え時にヘッダーのコントラストが不整合を起こす。

## 2. 仕様および要求事項 (修正方針の検討)
- [x] **案 1 (推奨・タグとアイコンを活用した多層的視認性担保)**:
  1. **ピン留め状態の多重視覚フィードバック**:
     - 背景色だけでなく、ピン留めアイコン（画像: `icon_manager.get_icon("pin")`）およびホットキー文字列による明示を維持・強化し、選択時でもピン留め状態が一目で識別できるようにする。
  2. **macOS における Treeview テキスト色と OS 外観の整合**:
     - macOS 環境では OS のアピアランス（Dark / Light）検知結果に追従し、`Treeview` のテキスト色（`foreground`）が背景との十分なコントラスト比を維持するように調整する。
  3. **選択マッピングの安全なフォールバック**:
     - macOS Aqua 環境において無理な `style.map` の空指定等を行わず、OS ネイティブの選択表示を許容しつつ、選択解除時に確実にピン留め色が復元されることを担保する。
- [ ] **案 2 (macOS 環境でも Treeview だけ強制的に 'clam' テーマを適用する)**:
  - Treeview のためだけにテーマを `clam` に切り替えると、他の Aqua ウィジェットとの調和が崩れ、ウィンドウ全体のレンダリング競合（黒画面化等の既知問題）を再発させるリスクがあるため不採用。
