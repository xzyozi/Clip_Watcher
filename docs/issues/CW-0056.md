# [CW-0056] [security] HashCalculatorComponent における入力長未検証の同期ハッシュ計算によるDoSおよびSHAKE系アルゴリズム選択時の未捕捉TypeError

## 0. メタ情報 (Scope & Impact)
- **検出テーマ**: セキュリティ
- **重要度**: Medium
- **関連Issue**: 該当なし
- **起票ステータス**: `stage:ideation` (agys 自律レビュー起票)

## 1. 概要・背景
大容量テキスト貼り付け時の同期ハッシュ計算によるGUIフリーズ（DoS）および、XOFアルゴリズム（SHAKE等）選択時の未捕捉TypeErrorによるクラッシュが発生します。

### 課題詳細 (Problem Detail)
HashCalculatorComponent では、テキストエリアの <KeyRelease> イベントによってキーストローク毎に _calculate_hash() が GUI メインスレッド（Tkinterイベントループ）上で同期実行されます。入力テキストのバイト長制限やデバウンス（遅延実行）制御が一切ないため、クリップボードから大容量データ（数MB〜数十MB）が貼り付けられた場合に毎回のキーストロークで UTF-8 エンコードおよびダイジェスト計算が走り、GUI 全体が長時間応答不能（フリーズ）になります。さらに、hashlib.algorithms_available に含まれる shake_128 や shake_256 などの可変長出力関数（XOF）は hasher.hexdigest() に必須引数 length を要求して TypeError を送出しますが、例外ハンドラが except ValueError: のみであるため未処理例外となりイベントハンドラがクラッシュします。また、Combobox に state='readonly' が指定されていないため、手動入力による任意文字列指定で予期せぬ例外が発生するリスクもあります。

- [ ] **案 2**: 案2（代替）: ハッシュ計算処理をバックグラウンドスレッド（concurrent.futures.ThreadPoolExecutor）に委譲し、計算完了後にメインスレッドへ結果を通知する非同期アーキテクチャを採用します。これにより入力サイズにかかわらず GUI の応答性を完全に担保できます。
