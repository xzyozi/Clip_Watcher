# [CW-0026] EventDispatcherのイベント契約を型安全化する

### 背景
`EventDispatcher` はリスナーを `Callable[[Any], None]` と定義していますが、実際には引数なし・複数引数・キーワード引数を許容しています。この不一致により、購読側で `# type: ignore` が増え、イベントのペイロード変更や引数不足をmypyで検出できません。

また、例外処理で `listener.__name__` を直接参照しているため、`functools.partial` やcallableオブジェクトが例外を出した場合に、エラー報告処理そのものが失敗する可能性があります。

### 改修方針

#### フェーズ1: 単一ファイルでの安全化
対象: `src/core/events/event_dispatcher.py`

- リスナー型を可変引数に対応した型へ見直す。
- `dispatch()` の実装と型定義を一致させる。
- ログ出力時のリスナー名取得を安全化し、`__name__` を持たないcallableでも例外処理が継続するようにする。
- このフェーズでは既存のイベント呼び出し方法を変更しない。

**目的:** 実行時の例外処理を堅牢化し、型定義と実装の明白な不一致を解消する。

#### フェーズ2: イベント契約の明示化
対象: `EventDispatcher` と全ての `subscribe()` / `dispatch()` 呼び出し元

- イベント名ごとにペイロード型を定義する。
- `HISTORY_UPDATED`、`SETTINGS_CHANGED`、`LANGUAGE_CHANGED` 等について、イベント名と引数仕様を固定する。
- `subscribe()` 側のリスナー引数と `dispatch()` 側のペイロードを型検査可能にする。
- 既存の `# type: ignore` を段階的に削除する。

**目的:** イベント名・ペイロード・リスナーのシグネチャ不一致を静的解析で検出できるようにする。

### 対象外
- イベントの非同期化
- イベントキューやスレッド間通信機構の導入
- イベント名そのものの大規模な改名
- 既存機能の振る舞い変更

### 受け入れ条件
- フェーズ1後、`EventDispatcher` が引数なし・複数引数・キーワード引数のイベント発行を安全に処理できる。
- callableオブジェクトや`partial`の例外発生時も、エラー報告処理が再例外にならない。
- フェーズ2後、主要イベントのペイロード不整合をmypyで検出できる。
- 不要な `# type: ignore` を削減できる。
