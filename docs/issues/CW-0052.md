# [CW-0052] [edge_cases] check_and_migrate_json における不正データ型・要素数に対する防御処理の欠落によるマイグレーションクラッシュ

- **重要度**: High
- **関連Issue**: 該当なし

## 1. 概要・背景
旧履歴 JSON からの移行時、要素数や created_at の型検証が不十分であり、破損値や非数値データが含まれていた場合に ValueError/TypeError が捕捉されずアプリ初期化がクラッシュする。

### 課題詳細 (Problem Detail)
check_and_migrate_json では、旧履歴 JSON の各要素 item がリストの場合に `len(item) == 3` のときのみ `created_at = float(item[2])` を実行している。しかし、item[2] が None や空文字列、あるいは日付形式文字列などの非数値であった場合、float() 変換は ValueError または TypeError を送出する。本メソッドの例外ハンドラ（L197-L212）は (json.JSONDecodeError, FileNotFoundError, OSError) および sqlite3.Error のみを捕捉しており、ValueError や TypeError を捕捉していない。そのため、1件でも破損したレコードが存在すると未処理例外が発生してマイグレーションが中断され、トランザクションがロールバックされないままアプリ起動処理がクラッシュする。さらに、`len(item) == 3` という厳密な等値判定を行っているため、将来の拡張や別バージョンでメタデータが付与されて要素数が4以上になった場合、タイムスタンプがスキップされて意図しない現在時刻に上書きされる境界値バグも抱えている。
