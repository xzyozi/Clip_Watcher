# [CW-0065] [security] logging_config における機密ログファイルのパーミッション制御欠落および安全でない空ファイル削除処理

## 0. メタ情報 (Scope & Impact)
- **検出テーマ**: セキュリティ
- **重要度**: Medium
- **関連Issue**: 該当なし
- **起票ステータス**: `stage:ideation` (agys 自律レビュー起票)

## 1. 概要・背景
ログディレクトリおよびファイルの作成時にアクセス権限制御が行われず機密情報が他ユーザーに露出するリスク、および空ログ削除時のTOCTOU競合・シンボリックリンク追従リスクが存在する。

### 課題詳細 (Problem Detail)
setup_logging において os.makedirs(log_dir, exist_ok=True) および DailyFileHandler でのログファイル作成時にパーミッション制御（アクセス権設定）が一切行われていない。クリップボード監視ツールではコピーされたパスワードやトークン、個人情報等の機微な情報や例外スタックトレースがログに出力される可能性があり、マルチユーザー環境において他ユーザーに平文ログが閲覧される情報露出リスクがある。さらに、起動時の空ログクリーンアップ処理（os.path.getsize(file_path) == 0 の判定後に os.remove(file_path) を実行）では、判定と削除の間にファイルが書き込まれる TOCTOU（Time-of-Check to Time-of-Use）競合状態が存在する上、シンボリックリンク（symlink / junction）の検証がないため、悪意ある空シンボリックリンクを経由した任意ファイル削除のリスクを内包している。また、ログの保持期間（Retention）制御がなく、ディスク消費による DoS の恐れもある。
